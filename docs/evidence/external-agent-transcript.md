## Why it is optional

The load-bearing transport evidence is reproducible and already in the repo:

- `docs/evidence/webmcp-transport-trace.json` — a captured
  `registerTool → getTools → executeTool → validation → gates → cancellation`
  chain through `document.modelContext`, regenerated by `npm run eval:webmcp`.
- The `/inspector` "chain verification" panel runs the same chain live and
  labels the active transport (native WebMCP vs the A11yMCP polyfill).
- `public/eval-results.json` — the measured benchmark, also dispatched
  through `document.modelContext.executeTool`.

A native third-party agent (ChatGPT in-app browser, or Chrome with a WebMCP
agent extension) would exercise the *native* `document.modelContext` instead
of the polyfill. That is a nice-to-have confirmation, not a prerequisite.

## Runbook (when a native WebMCP browser is available)

1. Open https://a11ymcp.vercel.app/demo in the agent browser.
2. Confirm `/inspector` shows "Native document.modelContext detected".
3. Ask the agent, verbatim: "I can only use a keyboard. Help me buy the
   NOMA Runner in size 9."
4. Record: discovered tool names, every tool call (name + arguments +
   result), any self-correction, the approval/confirmation pauses, and the
   final order id.
5. Repeat with: "I have low vision and need high contrast." — expect the
   agent to report `high_contrast` as unsupported and NOT fake it.
6. Paste the raw transcript below. Sanitize only PII.
