# Why A11yMCP

A11yMCP is a prototype exploring an agent-native accessibility layer for the
web. It is not a scanner, an overlay, or a generic browser agent.

## Accessibility scanners

Detect and report issues for developers to fix later. They cannot help a
user complete a task *now*, and they cannot negotiate what a site is willing
to adapt.

## Browser automation

Infers semantics from DOM and pixels, then actuates. It has no way to learn
which adaptations a site supports, no declared verification, and its only
remediation strategy is arbitrary DOM injection — brittle across sites and
unsafe by construction.

## Generic overlays

Apply client-side adaptations the site never declared as safe. They mutate
experiences without the site's consent or knowledge, which is exactly the
trust problem A11yMCP avoids.

## A11yMCP

user need → site-declared capability → agent negotiation → approved
adaptation → verification → task completion.

The website is a first-class participant: it declares what it can safely
adapt, how, and how to verify. The agent negotiates on behalf of the human
and never fakes unsupported capabilities.

## Evidence, not claims

- Captured WebMCP transport chain: docs/evidence/webmcp-transport-trace.json
  (registerTool → getTools → executeTool, schema + gate rejections,
  task-scoped unregisterTool; regenerated by `npm run eval:webmcp`)
- Measured WebMCP-vs-actuation comparison: public/eval-results.json
  (generated by `npm run eval:webmcp`; never hand-entered)
- Automated suites: `npm run test`, `npm run test:e2e`, `npm run eval:tools`
- Optional / pending: a recorded native-WebMCP agent run —
  docs/evidence/external-agent-transcript.md

We make no "world's first", WCAG-compliance, ADA-compliance, or
"works on every website" claims. This is a controlled prototype demonstrating
a contract-based interaction model.
